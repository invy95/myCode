## 一、先把两类「币圈岗」分开

很多人一听 crypto 就觉得是量化，其实 2026 年币圈招聘已经裂成两条线：

| 类型 | 典型 JD | 你要不要投 | 原因 |
|------|---------|:----------:|------|
| **A. Agent / AI 工程岗** | TOP 交易所 Agent 创新应用算法工程师 | ✅ **重点投** | JD 写的是 MCP/Skills/Agentic Coding/评测体系，不是 alpha 挖掘 |
| **B. 纯量化研究岗** | CEX 资深量化研究员、赋盟远程量化 | ❌ **不投** | 要订单簿微结构/C++/做市策略，你的优势用不上 |

你说「币圈量化很难进」——**判断正确**。但 **币圈 Agent 岗竞争面完全不同**：竞争者主要是 AI 工程师（不懂金融）和量化研究员（不懂 Agent 工程），你的交叉位置反而稀缺。

### 你的 AI 优势到底在哪（面试要说清楚）

不要讲「我会炒股」，要讲这三件事：

1. **Agent 工程闭环**：需求 → Skill/Tool 封装 → cron 部署 → 落盘断言 → 日志可观测（巨潮管道、盘中热度表）
2. **投研数据形态理解**：公告/预告/快报/分钟行情/板块热度——知道数据脏在哪、怎么兜底
3. **Agentic Coding 范式**：用 Cursor 以「人定义问题、AI 生成实现」交付，不是手写 CRUD

这三条正好对应天弘 JD 第 3–5 条、华创 JD 的 MCP/Skills、TOP 交易所 JD 的 Skills Composition + Harness。

## 三、LangGraph Demo 方案（3–5 天，解锁 Tier A）

### 目标

把现有 **巨潮净利润采集 Skill** 用 LangGraph 重写一版，作为公开 Repo 作品集。  
不改业务逻辑，只换框架——这是「同义翻译」，不是造假。

### 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 编排框架 | **LangGraph** | 天弘/华创/国信 JD 都点名 |
| 模型 | DeepSeek / 通义 API | 成本低，面试够用 |
| 工具 | @tool 装饰器封装现有函数 | 对应 MCP/Skills 叙事 |
| 状态 | TypedDict State + checkpoint | 展示「可观测与回放」 |
| 评测 | 5 条固定输入 + 断言 | 对应华创 JD 的 Benchmark/回归测试 |

### 图结构（4 个节点）

```
START → fetch_pdf → parse_table → validate → [fail→retry] → persist → END
```

| 节点 | 功能 | 对应现有能力 |
|------|------|-------------|
| `fetch_pdf` | 巨潮下载 + 东财兜底 | 多源召回与降级 |
| `parse_table` | PDF 表格提取 | 非结构化解析 |
| `validate` | 断言校验（净利同比、公告日） | 评测集/回归测试 |
| `persist` | 落盘 CSV/SQLite | 生产管道 |

### 交付物清单

1. `README.md`：架构图 + 运行方式 + 与天弘/华创 JD 的能力映射表
2. `graph.py`：LangGraph 主图（带 checkpoint）
3. `tools/`：3 个 @tool 函数
4. `eval/`：5 条评测用例 + `pytest` 断言
5. `demo.mp4` 或终端录屏：30 秒跑通全流程

### 简历新增一行（demo 完成后）

> 基于 LangGraph 构建投研公告解析 Agent，实现 PDF 采集→结构化提取→断言校验→落盘全链路，配套 5 条回归评测用例，支持 checkpoint 断点续跑。
